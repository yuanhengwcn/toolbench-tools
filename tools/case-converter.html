The conversions are mechanical, but consistency matters more than which convention you pick. A codebase with getUserName, get_user_email and GetUserPhone costs every reader a small context switch, every time.

How words get split

Converting userProfileImageURL correctly requires knowing it is four words, not two or six. This tool splits on three signals, in order:

  1. A lowercase or digit followed by an uppercase — userProfile → user Profile.
  2. A run of capitals followed by a capital and a lowercase — ImageURL → Image URL.
  3. Separators — underscores, hyphens, dots and spaces.

The second rule is the one naive converters miss, which is why parseHTTPResponse becomes parse_h_t_t_p_response in some tools and parse_http_response here.

Acronyms are a judgement call

There is no universal answer for userID versus userId. Both appear in widely used libraries. The pragmatic rule most style guides land on: treat an acronym as a single word when it starts a name (UserId), and keep it fully uppercase inside CONSTANT_CASE and Title Case where readability wins. Whatever you choose, apply it everywhere.

Frequently asked questions

Does it preserve punctuation?

Separators (underscore, hyphen, dot, space) are treated as word boundaries and normalised to whichever style you pick. Other punctuation is dropped, because it is almost never valid in an identifier.

What happens to numbers?

Digits stay attached to the preceding word: version 2 api becomes version2Api. This matches how most linters treat them, though a few enforce a separator before digits.

Can I convert a whole paragraph?

The identifier styles (camel, snake, kebab) assume a phrase, not prose, and will run every word together. For running text use Sentence case or Title Case, which preserve spaces.
