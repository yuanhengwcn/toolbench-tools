How to use this JSON formatter

  1. Paste or type your JSON into the left box.
  2. Press Format to reindent it, or Minify to strip every unnecessary character.
  3. Copy the result with the Copy button, or drag-select from the output box.

If the JSON is invalid, this tool reports the line and column where parsing failed along with a snippet of the surrounding text, so you can jump straight to the problem instead of hunting through a 4,000-line payload.

Format or minify — which one do you need

Pretty-printed JSON is for humans: it uses newlines and indentation so nested structures are readable, at the cost of a much larger payload. Minified JSON removes all optional whitespace and is what you want in production — in an API response, a config file that ships with an app, or a fixture you commit to a repository.

The practical rule: minify what machines read, format what you read. If you are debugging a response, format it. If you are pasting a value into a header or an environment variable, minify it.

Common JSON syntax errors this catches

  • Trailing commas. {"a":1,} is invalid in JSON, even though JavaScript object literals allow it.
  • Single quotes. JSON strings must use double quotes. {'a':1} is not valid JSON.
  • Unquoted keys. {a:1} fails — every object key must be a quoted string.
  • Comments. JSON has no comment syntax. // or /* */ will break parsing.
  • Missing commas. Elements in an array or object must be separated by commas.
  • Unescaped control characters. A literal newline inside a string is invalid; it must be written as \n.

Frequently asked questions

Is my JSON uploaded anywhere?

No. Parsing and formatting run in JavaScript inside this browser tab. The page works with the network disconnected, and no request is made with your input.

How large a file can it handle?

Comfortably up to a few megabytes. Beyond roughly 10 MB the bottleneck becomes the browser's text rendering rather than the JSON parser, and the page may feel sluggish.

Does it preserve key order?

Yes. JSON.parse keeps insertion order, with one exception: keys that look like array indices (for example "0", "1") are ordered numerically first, because that is how JavaScript objects behave. Use Sort keys if you want a deterministic alphabetical order.

Why does it reject JSON that a YAML parser accepts?

Because YAML is a superset of JSON, not the other way around. YAML tolerates comments, unquoted strings and indentation-based nesting, all of which JSON forbids. This tool validates strictly against RFC 8259.

Can it convert JSON to another format?

Not yet — JSON to CSV, YAML and TypeScript interfaces are on the roadmap. The contact page is the fastest way to move one up the list.
