What Base64 actually does

Base64 is not encryption and not compression. It is an encoding that rewrites arbitrary bytes using only 64 printable ASCII characters, so binary data can travel through channels that only accept text — email bodies, JSON strings, XML attributes, HTTP headers, data URIs.

Every 3 bytes of input become 4 characters of output, which is why Base64 data is about 33% larger than what it encodes. If you are looking at a 4 MB Base64 blob, the original was roughly 3 MB.

Why most Base64 tools corrupt your text

The browser's built-in btoa() only accepts one byte per character. Feed it a Chinese, Arabic or emoji string and it throws InvalidCharacterError, or silently produces mojibake if the caller mangled the input first. The fix is to UTF-8 encode the string into bytes before calling btoa(), and to UTF-8 decode after atob(). This tool does that for you in both directions.

// Correct UTF-8 safe encoding
const bytes = new TextEncoder().encode(text);
const b64 = btoa(String.fromCharCode(...bytes));

// Correct decoding
const bin = atob(b64);
const text = new TextDecoder().decode(Uint8Array.from(bin, c => c.charCodeAt(0)));

Standard vs URL-safe alphabet

Standard Base64 uses + and /, and pads with =. Those characters are problematic in URLs: + is interpreted as a space in query strings, and / collides with path separators. URL-safe Base64 (RFC 4648 §5) substitutes - and _, and usually drops the padding. JWT tokens, for example, use URL-safe Base64 without padding.

If you are decoding something that came out of a JWT or a signed URL, tick URL-safe alphabet first — otherwise you will get a decode error on the first - or _.

Frequently asked questions

Is Base64 secure enough for passwords or API keys?

No. Base64 is fully reversible by anyone — echo 'c2VjcmV0' | base64 -d returns the original. Never treat Base64 as protection. For secrets you need encryption (AES-GCM, age) or a secret manager.

Why does my decoded output contain question marks?

Usually the source was not UTF-8. Windows tools often emit GBK or Latin-1, and those bytes are not valid UTF-8, so the decoder substitutes replacement characters. This tool assumes UTF-8; if your source is another encoding it must be converted before Base64 encoding.

Can I paste a Base64 image and see it?

Decode it and the output will be the raw Data URI text. To view it, paste that string into the address bar of a new tab — browsers render data:image/png;base64,… URLs directly.

Why is the output 33% bigger?

Encoding overhead. 6 bits of payload are stored per 8-bit character, so 3 input bytes expand to 4 output characters. Padding with = accounts for the final partial group.
