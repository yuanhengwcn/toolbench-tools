JWT Decoder

Paste a JSON Web Token to read its header and claims, and see exactly when it expires.

Decoding is not verification. This tool reads the token the same way anyone holding it can. It does not check the signature, so a token shown as "valid" here could still be forged. Never treat a decoded token as proof of identity.

What a JWT actually contains

A JSON Web Token is three base64url-encoded segments joined by dots: header.payload.signature. The first two are just JSON — base64url encoding is reversible by anyone, which is why a token must never carry secrets in its payload.

The header declares the signing algorithm (alg) and token type. The payload holds claims — statements about the subject, the issuer, and validity windows. The signature is a cryptographic tag over the first two segments, and it is the only part that provides any guarantee.

Registered claims and what they mean

issIssuer — who created the token
subSubject — usually the user ID
audAudience — who the token is for
expExpiry, seconds since epoch
nbfNot before, seconds since epoch
iatIssued at, seconds since epoch
jtiUnique token ID, used for revocation

All three time claims are numeric dates in seconds, not milliseconds. Getting that wrong is the single most common JWT bug: multiplying by 1000 in one place and not the other puts your token 50,000 years out.

How a server should validate a token

  1. Split the token and decode the header to read alg.
  2. Reject alg: none, and pin the algorithm to the one you expect — never let the token choose it. This is the classic algorithm-confusion attack.
  3. Verify the signature with the correct key (HMAC secret, or the issuer's public key fetched from JWKS).
  4. Check exp, and nbf if present.
  5. Check iss and aud match your service, not just that they exist.

Steps 2 through 5 are all things a decoder cannot do for you. That is the whole point of the warning above.

Frequently asked questions

Is it safe to paste a production token here?

This tool decodes in your browser and transmits nothing, so the token does not leave your machine. That said, a live token is a bearer credential — anyone who has it can act as that user until it expires. Prefer an expired or test token when you can.

Why does my token show as expired when it should not be?

Either genuine expiry, clock skew between the issuing server and yours, or a units mistake. Compare exp against the current epoch value on the timestamp converter — if the difference is measured in decades rather than minutes, the value was written in milliseconds.

Can this tool verify the signature?

Not in this version. Verification needs the signing key, and asking users to paste a secret into a web page is a bad habit to encourage. Do it server-side with a maintained library, or in a local script.

What is the difference between JWT and JWE?

JWT (JWS) is signed — the contents are readable but tamper-evident. JWE is encrypted — the payload is opaque without the decryption key. If confidentiality matters, you need JWE; a plain JWT is the wrong tool, no matter what the signature says.
