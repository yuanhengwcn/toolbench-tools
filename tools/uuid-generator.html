About UUID version 4

A v4 UUID is 122 bits of randomness plus 6 bits identifying the version and variant. It contains no timestamp, no machine identifier and no sequence number, which is exactly why it is the default choice for primary keys in distributed systems: two services can generate UUIDs independently and never collide.

The canonical string form is 32 hexadecimal digits in five groups — xxxxxxxx-xxxx-4xxx-yxxx-xxxxxxxxxxxx, where 4 marks the version and y is one of 8, 9, a or b.

Why the random source matters

Plenty of online generators use Math.random(), which is a fast non-cryptographic PRNG. Its output is predictable enough that an attacker who observes a few values can narrow down the internal state. For identifiers that end up in URLs, session tokens or invitation links, that is a real problem.

This tool uses crypto.getRandomValues(), the platform CSPRNG, and falls back to crypto.randomUUID() where available. Both draw from the operating system's entropy source.

UUID vs auto-increment integers

  • Integers are compact (8 bytes), sort naturally and index efficiently — but they leak record counts, require a central sequence, and make sharding awkward.
  • Random UUIDs need no coordination and leak nothing, but at 16 bytes they bloat indexes, and their randomness hurts B-tree locality on inserts.
  • UUIDv7 is the modern compromise: time-ordered so index inserts stay sequential, still globally unique. If you are choosing today and your database supports it, v7 is usually the better default.

Frequently asked questions

Can two generated UUIDs ever collide?

In theory yes, in practice no. With 122 random bits you would need to generate about 2.7×1018 UUIDs before a 50% chance of a single collision. Generating a billion per second, that is roughly 86 years of continuous generation.

Are these UUIDs safe to use as API tokens?

They are unguessable enough that brute force is impractical, but they are not a substitute for a session token design: they carry no expiry, no signature and no scope. Use a signed token (JWT with an HMAC, or an opaque token stored server-side) for anything security-relevant.

Why do some UUIDs start with a number and others with a letter?

Because every character is independently random hexadecimal. There is no structural prefix in v4 — uniformity is the point.

Do you log the generated values?

No. Generation happens in your browser and nothing is transmitted. You can verify this by generating UUIDs with the network tab open or the connection disabled.
