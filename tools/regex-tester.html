How matching works here

The pattern is compiled with your chosen flags and always run in global mode, so every non-overlapping match in the text is reported. Each entry in the match list shows the matched substring, its character offset, and the contents of any capture groups.

Group 0 is always the full match. Numbered groups follow the order their opening parentheses appear. If your pattern fails to compile — an unclosed group, an invalid quantifier, a bad escape — the error message from the engine is shown verbatim so you can locate the problem.

The four flags, and what each one changes

i — ignore caseCase-insensitive
m — multiline^ and $ match at line breaks
s — dotall. matches newlines too
u — unicodecode points, not code units

The u flag is the one people forget. Without it, an emoji or a character outside the Basic Multilingual Plane is treated as two separate UTF-16 code units, so . can match half a character and character classes behave unexpectedly. If you are matching user-supplied text with non-Latin scripts, turn it on.

The g flag exists too, but it is implicitly on here: its only effect in a tester would be to decide whether you see one match or all of them.

Greedy versus lazy quantifiers

.* is greedy: it takes as much as possible, then backtracks until the rest of the pattern can match. .*? is lazy: it takes as little as possible and expands only when forced. On the string <b>bold</b> the pattern <.*> matches the whole thing, while <.*?> matches just <b>.

Backtracking is also where regex performance explodes. Nested quantifiers like (a+)+$ against a long string of as can hang for seconds — this is catastrophic backtracking, and it is the reason some validators impose timeouts on user-supplied patterns.

Frequently asked questions

Is this JavaScript regex or PCRE?

JavaScript — the engine is the one built into your browser, so the syntax is what you would write in a RegExp literal or new RegExp(). PCRE, Python's re and PHP's preg_* have extra constructs such as (?P<name>…), \A and possessive quantifiers that will fail here.

How do I do a named capture group?

Use (?<name>pattern) and read the result from match.groups.name. Browser support is broad now; older engines require numbered groups instead.

Why does my pattern match an empty string repeatedly?

A pattern that can match zero characters — a*, \b, (?:) — will produce an empty match at every position. Any correct global loop has to advance lastIndex manually in that case, otherwise it never terminates. This tester handles it, but your own code probably does not.

Can I generate a pattern from example text?

No, and be wary of tools that claim to. A pattern inferred from examples encodes only the samples you gave it, and will either over-match or break on the next real input. Writing the pattern from the grammar of the data is faster than debugging an inferred one.
