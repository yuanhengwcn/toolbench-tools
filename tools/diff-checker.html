How this comparison works

The tool splits both texts into lines, then computes a longest common subsequence between them. Lines in that subsequence are unchanged; everything else is either an addition (present only on the right) or a deletion (present only on the left). This is the same algorithm family behind git diff, though production diff tools add heuristics to make the output easier to read on large files.

The comparison is line-level, not character-level. A single changed character marks the whole line as removed and re-added — which is usually what you want when reviewing a config file, and not what you want when proofreading prose.

Why whitespace and case options matter

Most noisy diffs are not real changes. A formatter run that converts tabs to spaces, a line-ending difference (CRLF versus LF), or a key that changed case will light up hundreds of lines that are semantically identical. Ticking ignore whitespace normalises runs of spaces and trims line ends before comparing; ignore case folds to lowercase. Neither changes what is displayed — only what counts as a match.

If enabling both makes your diff disappear entirely, the "change" was formatting. That is worth knowing before you spend time reviewing it.

When to use a real diff tool instead

For anything beyond a few hundred lines, use the tool that already knows your file: git diff, VS Code's built-in comparison, or diff -u. They handle binary files, detect moved blocks, integrate with your editor, and do not require copy-pasting content into a browser. This page is for the quick check — two API responses, an environment file, a config that broke in production.

Frequently asked questions

Is there a size limit?

Around 2,000 lines per side. The algorithm's memory use grows with the product of the two line counts, so a 5,000 × 5,000 comparison would need roughly 100 MB and would freeze the tab. Past the limit the tool refuses rather than hanging.

Does it detect moved lines?

No — a moved block shows as a deletion plus an addition in the new position. Detecting moves requires a second alignment pass, which real diff tools do and this one does not.

Why does my diff show every line as changed?

Almost always a line-ending mismatch. Windows CRLF versus Unix LF, or a file saved with a BOM, makes every line differ byte-wise. Re-save with consistent line endings, or tick ignore whitespace.

Is my text sent anywhere?

No. The comparison runs in this tab. That matters here more than usual — people diff environment files and configuration containing credentials.
