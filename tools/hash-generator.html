Which algorithm should you use

MD5Broken. Collisions are cheap to produce.
SHA-1Broken. Practical collisions since 2017.
SHA-256Recommended default, any purpose.
SHA-512Faster than SHA-256 on 64-bit hardware.

The honest summary: use SHA-256, or better, a purpose-built function. MD5 and SHA-1 are still included here because you will keep meeting them — in ETags, in legacy checksum files, in Java's MessageDigest.getInstance("MD5") — and sometimes you need to reproduce a value an old system produced.

Why a fast hash is wrong for passwords

SHA-256 is designed to be fast. On a modern GPU you can compute billions of them per second, which is exactly what an attacker wants. A database of SHA-256 password hashes falls to a wordlist attack in minutes.

Password storage needs a deliberately slow, memory-hard function with a per-user salt: Argon2id (preferred), scrypt, or bcrypt if the others are unavailable. The salt is what stops a single rainbow table from cracking every row at once. If you remember one thing from this page, make it that.

Hashing versus encryption versus encoding

  • Hashing is one-way. There is no key and no inverse — verifying means hashing the candidate again and comparing.
  • Encryption is reversible with a key. Use it when you need the original data back (AES-GCM).
  • Encoding (Base64) is reversible by anyone. It provides no security at all.

How a hash is used to verify a download

# macOS / Linux
shasum -a 256 file.iso

# Windows PowerShell
Get-FileHash file.iso -Algorithm SHA256

# Compare against the published value — an exact match means the bytes
# are identical to what the publisher hashed.

This is also how ETags work and how content-addressed storage (Git, Docker layers, IPFS) deduplicates: the hash is the identity of the content.

Frequently asked questions

Is my file uploaded to a server?

No. The file is read with FileReader and hashed in memory. Even a multi-gigabyte file never leaves the browser tab, though very large files will take a few seconds to process.

Why is MD5 not available through the browser's crypto API?

Because Web Crypto deliberately implements only algorithms considered secure. MD5 has been excluded since the standard was written. This page therefore ships its own MD5 implementation, verified against reference vectors including multi-block and UTF-8 inputs.

Do hashes change if I hash the same text twice?

No — a cryptographic hash is deterministic. The same bytes always produce the same digest. If you get a different value, the input differed: a trailing newline, a BOM, CRLF instead of LF, or different text encoding.

Can I reverse a hash?

Not in general. You can only guess inputs and hash them to see if they match. Sites offering "MD5 decryption" are running a lookup table of common strings — they will crack password123 and fail on anything with real entropy.
