About Toolbench

A small collection of tools I wanted to exist.

Who runs this site

I'm a backend developer working mostly in Java and .NET, building supply-chain software for hospitals. Toolbench is a side project: a place to put the small utilities I kept opening other people's websites for, and to finally own the whole stack of something I use every day.

I write the code, the explanations and the mistakes myself. There is no content team and no AI-generated filler — though I do use AI assistance to draft and edit, the same way I'd use a compiler.

Why another tool site

Because the existing ones kept losing my input. Paste a JWT into a decoder and it goes to a server; paste a config file into a formatter and it ends up in someone's request log. Most of these tools need nothing but a parser, so there is no good reason for your data to leave the browser.

The other annoyance is the interface. A tool should open, work, and get out of the way — no modal asking me to subscribe before I can press a button, no 4,000-word preamble before the input box.

The principles

  • Local first. If a tool can run in JavaScript, it runs in JavaScript. No server round-trip, no upload, no queue.
  • Explain the mechanism. Each tool page says how the underlying operation actually works, including the edge cases that bite people — unit confusion, UTF-8 mishandling, timezone drift.
  • No dark patterns. No forced signup, no fake countdowns, no "download our app" interstitials.
  • Free, supported by ads. There are no paid tiers. The site runs on advertising, which is why you will see ad slots on the pages.

How the site is built

Plain HTML, CSS and JavaScript. No framework, no build step, no bundler. Each page is a static file, which means it loads fast on a slow connection and does not break when a dependency publishes a breaking change. Hosting is on a static edge network.

That choice is deliberate: a tool that depends on forty npm packages is a tool that will stop working eventually for reasons unrelated to the tool.

What I'm working on next

Regex testing with live highlighting, JWT decoding and signature verification, hash generation (MD5/SHA-1/SHA-256), and a proper cron expression parser. After that, whatever people ask for most — the contact page is the input channel for that.

Corrections

If a tool produces a wrong result, or an explanation on this site is inaccurate, I want to know. Technical errors are the one thing I take seriously enough to fix the same week.
